# Методические указания для преподавателей по работе с ФОС и оцениванию

## 1. Общие принципы

ФОС построен на компетентностно-ролевой модели КРМ 3.0.  
Оценивание должно проверять **наблюдаемые действия** и **артефакты**, а не только знание терминов.

Единая 100-балльная система обязательна. Все модульные рубрики должны быть согласованы с весами в `MEASUREMENT_MODEL_detailed.md` и `README.md`.

## 2. Сценарии контроля

### Текущий контроль (М1)
- Архитектурный кейс.
- Рубрика: корректность анализа сценария, обоснованность выбора архитектуры, качество схемы потоков данных.
- Макс. 10 баллов.

### Рубежный контроль (М2–М4)
- Практические работы.
- Обязательные артефакты: воспроизводимый код/notebook, отчёт с метриками, Data Card (для данных), демонстрация интеграции (для М4).
- Используйте чек-листы и эталонные ответы, размещённые в модульных `kim-*.md` / docx.

### Промежуточная аттестация
- **Экзамен** (20 баллов): 40 % теория (билеты) + 60 % практика (мини-задача на данные/модель/интеграцию).
- **Защита проекта** (25 баллов):
  - Инженерное решение и работающий прототип — 60 %
  - Анализ, документация, риски — 25 %
  - Презентация и ответы — 15 %

### Peer-review
- 5 баллов. Студенты оценивают работы друг друга по единой рубрике. Преподаватель проверяет адекватность оценок.

## 3. Процедура оценивания

1. Проверить полноту и воспроизводимость артефактов.
2. Применить рубрику КИМ (баллы за критерии).
3. Зафиксировать обратную связь (что улучшить).
4. Выставить баллы в единую ведомость.
5. При спорных случаях — коллегиальное обсуждение или апелляция.

## 4. Разрешение спорных случаев и апелляций

- Студент может подать апелляцию в течение 3 рабочих дней после объявления результатов.
- Апелляция рассматривается преподавателем + (при необходимости) вторым экспертом.
- Основания: ошибка в подсчёте, несоответствие рубрике, технический сбой.
- Решение фиксируется письменно.

## 5. Использование ресурсов и генеративного ИИ преподавателем

- Разрешено использовать LLM для генерации вариантов заданий, эталонных решений и рубрик — с обязательной экспертной проверкой.
- Нельзя полностью полагаться на сгенерированные ключи без валидации на реальных данных.
- Все эталонные решения должны быть воспроизводимы.

## 6. Рекомендации по проведению модулей

- **М1–М2:** акцент на понимание полного цикла и качество данных.
- **М3:** требовать сравнение baseline vs улучшенная модель, анализ ошибок.
- **М4:** обязательно демонстрация работающей интеграции (хотя бы на эмуляторе).
- **М5:** контролировать вклад каждого участника команды.

## 7. Заполнение и обновление ФОС

- При изменении КИМ обновлять ссылки в модели измерения.
- Следить за согласованностью баллов.
- После каждого семестра собирать обратную связь и обновлять рубрики.
