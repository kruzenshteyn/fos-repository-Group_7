# Методические указания для обучающихся

## 1. Общий маршрут освоения дисциплины

Дисциплина состоит из 5 модулей (180 часов). Рекомендуемый порядок:

1. **М1 (недели 1–3)** — изучение архитектуры → выполнение архитектурного кейса.
2. **М2 (недели 4–9)** — работа с сенсорными данными и MQTT → сдача практических работ.
3. **М3 (недели 10–18)** — обучение моделей (включая unsupervised, CV, NLP, RL) → сдача практик.
4. **М4 (недели 19–26)** — интеграция с Home Assistant и Edge → сдача работ по развёртыванию.
5. **М5 (недели 27–32)** — командный проект → peer-review → экзамен → защита.

Все материалы модулей находятся в каталогах `M1-…` – `M5-…`.  
Актуальная модель измерения и баллы приведены в [РПД](../../docs/rpd.md) и [матрице КРМ](../../docs/quality/measurement-model.md).

## 2. Требования к среде выполнения

- Python 3.10+  
- Рекомендуемые библиотеки: см. `requirements.txt` (после добавления)  
- Home Assistant (локальная установка или Docker)  
- MQTT-брокер (Mosquitto)  
- Для Edge: Raspberry Pi / эмулятор / Google Colab + TFLite / ONNX  
- Git + GitHub для сдачи артефактов  

При отсутствии физического оборудования допускается использование симуляторов и [учебных датасетов](../../resources/datasets/README.md).

## 3. Правила сдачи артефактов

- Каждый практический КИМ сдаётся в виде:
  - отчёта (Markdown или PDF),
  - кода / notebook (воспроизводимый),
  - при необходимости — демо-видео или скриншотов работающей системы.
- Срок сдачи указывается в каждом КИМ (обычно конец соответствующей недели).
- Формат именования: `Group7_M{N}_{ФИО}_{название_работы}`.
- Обязательна воспроизводимость: requirements, seed, описание данных.

## 4. Командная работа и peer-review

- Проект (М5) выполняется в командах 3–4 человека.
- Peer-review проводится по рубрике, размещённой в ASSESSMENT_TOOLS.md.
- Каждый участник обязан указать свой вклад в `team/` и в итоговом отчёте.

## 5. Академическая честность и использование LLM / генеративного ИИ

- Разрешено использовать LLM (ChatGPT, Claude, Grok и др.) для:
  - объяснения концепций,
  - генерации черновиков кода с обязательной проверкой и доработкой,
  - помощи в написании документации.
- **Запрещено:**
  - сдавать сгенерированный код/текст без понимания и существенной доработки,
  - копировать чужие решения без указания источника,
  - использовать LLM на экзамене и при устной защите без разрешения преподавателя.
- В отчёте обязательно указывать, какие части были созданы/существенно доработаны с помощью ИИ (раздел «Использование инструментов ИИ»).

## 6. Критерии успешного прохождения

- Набрать ≥ 60 баллов из 100.
- Сдать все обязательные практики М1–М4.
- Успешно защитить проект и сдать экзамен.
- Соблюдать сроки и требования к воспроизводимости.

## 7. Куда обращаться

- Вопросы по содержанию модулей — ведущему преподавателю или автору материала из [состава команды](../../team/README.md).
- Технические проблемы с репозиторием / сдачей — в Issues репозитория или преподавателю.
- Апелляции по оцениванию — по процедуре, описанной в методических указаниях для преподавателей.
